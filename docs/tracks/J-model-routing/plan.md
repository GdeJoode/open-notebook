### 1.2 Hard guardrail — embeddings + parsing stay LOCAL and FIXED (J-Q2)

> **This is a blocking invariant, not a preference. Any phase that touches it is auto-REVISIONS_NEEDED.**

- **Embeddings** are resolved via `get_embedding_service()` in `dependencies.py:495` using `DefaultModels.default_embedding_model`. **J MUST NOT route this through the provider chain.** Cloud embeddings change the vector space and dimensionality; Track I.G pins the HNSW index to **768-dim `nomic-embed-text`**. A cloud embedding (OpenAI `text-embedding-3` = 1536/3072-dim) would silently corrupt vector search.
- **Parsing** (docling / MinerU, Track A) is GPU-service-bound and never an LLM call in the routing sense.
- **Enforcement mechanism** (built in J.3, tested in J.6): the route resolver's public surface accepts only an `LLMTask` enum = `{ENTITY_EXTRACTION, SUMMARIZATION, CHAT}`. There is **no** `EMBEDDING` / `PARSING` member. A unit test asserts the enum has exactly these three members and that `get_embedding_service` / the parsing dispatch import **nothing** from `app_main.services.model_routing`. A grep-guard test (`assert "model_routing" not in embedding_service_source`) is the falsifiable canary.

### Phase J.1 — Provider-chain config + privacy-aware ordered-route resolver

**Goal**: introduce the ordered provider-chain config and a single resolver that, given an `LLMTask` and a resolved privacy mode, returns the **ordered list of candidate `model` rows** to attempt. Generalizes B.8's `resolve_default_model_id` from "one model id" to "ordered route". **No failover execution yet** (that is J.2) — this phase produces the *plan*, J.2 *executes* it. No behavior change to live extraction/chat: the resolver is wired but the executor still calls only the first entry until J.2.

**Files to create**:
- `migrations/51.surrealql` + `migrations/51_down.surrealql` — `DEFINE TABLE model_route SCHEMAFULL;` (see J-D1 below for why a table over `DefaultModels` extension). Fields:
  - `task` — `string` (`entity_extraction` | `summarization` | `chat`)
  - `provider_chain` — `array` (ordered list of `{provider: string, model_id: record<model>, enabled: bool}`; FLEXIBLE `option<object>` entries for forward-compat — A.1c lesson)
  - `private_chain` — `array` (ordered list, local providers only; same shape)
  - `updated_at` — `datetime DEFAULT time::now()`
  - One row per task; singleton-per-task semantics enforced in the repo.
- `apps/app-main/src/app_main/services/model_routing/__init__.py`
- `apps/app-main/src/app_main/services/model_routing/route_resolver.py` — `LLMTask` enum (exactly `ENTITY_EXTRACTION`, `SUMMARIZATION`, `CHAT`), `PrivacyMode` enum (`CLOUD`, `PRIVATE`), `ResolvedRoute` dataclass (`ordered_candidates: list[ModelCandidate]`, `mode: PrivacyMode`), and `async resolve_route(task, mode) -> ResolvedRoute`. Resolution:
  1. Load `model_route` row for the task (fall back to a hard-coded default chain — see §4 J-Q3 default — if no row).
  2. If `mode == PRIVATE`: use `private_chain` (local providers only). If empty, derive from `provider_chain` by filtering to `is_local` providers.

  5. Filter out `enabled == False` entries and `model.is_enabled == False` rows.
  6. **Preserve B.8 head-of-chain precedence**: the per-task default model (`default_extraction_model` for extraction, etc.) is honored as the model id for its provider entry; an explicit per-call `model_id` override still wins (mirrors B.8's `resolve_default_model_id`).

- `packages/surrealdb-service/tests/test_model_route_repository.py` — roundtrip under the B.0 testcontainers harness.

### Phase J.2 — Per-provider health + circuit-breaker + per-document failover executor

**Goal**: execute a `ResolvedRoute` with **per-document failover** (J-Q4): try the first available provider; on a provider failure, fail the **whole document's LLM stage** over to the next candidate; local is the last resort (cloud mode). Add per-provider health tracking + a circuit-breaker so a dead provider is skipped fast (J-Q5).

**Files to create**:
- `apps/app-main/src/app_main/services/model_routing/circuit_breaker.py` — in-process `ProviderCircuitBreaker` keyed by provider name. States `CLOSED`/`OPEN`/`HALF_OPEN`; opens after N consecutive failures (default 3), cools down for T seconds (default 60), probes one request in `HALF_OPEN`. Thread-safe (asyncio lock). In-memory is acceptable for V1 (single-process worker); persistence is a J-D3 decision point.
- `apps/app-main/src/app_main/services/model_routing/failover_executor.py` — `async execute_with_failover(route: ResolvedRoute, call: Callable[[ModelCandidate], Awaitable[T]]) -> FailoverResult[T]`. Iterates `route.ordered_candidates`, skips `OPEN` breakers, invokes `call`, on a **failover-eligible** exception (mapping owned by J.4) records the breaker failure + a fallback telemetry event and advances to the next candidate; on success records the breaker success + the served provider. Raises `AllProvidersFailedError` only when every candidate is exhausted. Returns `FailoverResult(value, served_provider, served_model_id, attempts: list[AttemptRecord])`.
- `apps/app-main/tests/test_circuit_breaker.py`
- `apps/app-main/tests/test_failover_executor.py`

**Files to modify**:
- `apps/app-main/src/app_main/services/model_routing/route_resolver.py` — add `is_provider_healthy(provider)` helper reading the breaker (used to pre-sort/skip; the executor is still authoritative).
- `apps/app-main/src/app_main/dependencies.py` — `get_circuit_breaker_registry()` (process singleton) + `get_failover_executor()`.

**Acceptance criteria** (falsifiable):
1. Given a 2-provider route where the first `call` raises a failover-eligible error and the second succeeds, `execute_with_failover` returns `served_provider == <second>` and `attempts` has length 2 with the first marked failed.
2. After 3 consecutive failures for provider P, P's breaker is `OPEN`; the next `execute_with_failover` **skips P without calling it** (assert `call` is not invoked for P) and records a `skipped_open_circuit` attempt.
3. After the cooldown, the breaker transitions to `HALF_OPEN` and a single probe call is allowed; success → `CLOSED`, failure → `OPEN` again.
4. When **all** candidates fail, `AllProvidersFailedError` is raised carrying the per-attempt records (not a generic exception).
5. A **non**-failover-eligible exception (e.g. a programming `TypeError`) propagates immediately without advancing to the next provider (we don't mask bugs as failover — RULES "fix don't workaround").
6. The executor records exactly one `served_provider` telemetry field per successful document stage (feeds J-Q7).

**Tests required**:
- Unit (`test_circuit_breaker.py`): 5 scenarios — open after N, skip when open, half-open probe success, half-open probe failure, independent per-provider state.
- Unit (`test_failover_executor.py`): failover-on-error, skip-open-circuit, all-failed, non-eligible-propagates, served-provider recorded.

**PR boundary**: ONE PR titled `feat(routing): per-document failover executor + provider circuit-breaker (J.2)`.

**Effort estimate**: **2-2.5 days**. Reviewer cycle budget: ×1.5.

**Risk mitigations**: failover-eligibility is a **whitelist** (J.4 maps known transient/provider errors); everything else propagates — prevents masking real bugs. In-memory breaker is explicitly scoped V1; J-D3 captures the multi-worker question.

## 4. Decision points (escalate to user before / during implementation)

- **J-D1 — `model_route` table vs extend `DefaultModels`** (resolve at J.1):
  - *Recommendation*: **new `model_route` table**. `DefaultModels` is a single flat singleton of scalar model-id fields; an **ordered chain per task** is a list-of-objects with per-entry enable flags and a separate private-chain — it does not fit the scalar schema cleanly, and overloading `DefaultModels` would force every chain edit to rewrite the whole singleton. A table also gives per-task rows the UI can edit independently. `DefaultModels` per-function fields stay as the **head-of-chain default model** (B.8 contract preserved). *Trade-off*: one more table + migration vs. reusing an existing record. **Recommended: table.**
- **J-Q3-id — exact Anthropic Claude model id**: must be filled from the **`claude-api` skill/reference at implementation time** (not installed in the planning sandbox). Do not hardcode a stale id. The default chain seeds the Anthropic candidate's `model.name` from that reference; OpenAI's default likewise (`gpt-4o`-class current id). *This is the one item the implementer cannot self-resolve from the codebase.*
- **J-D3 — circuit-breaker persistence**: V1 is **in-process** (single worker). If/when app-main runs multiple worker processes, breaker state diverges per worker. *Recommendation*: ship in-memory for V1, note the multi-worker limitation in `OPERATOR_GUIDE.md`; persist to SurrealDB only if multi-worker failover correctness becomes a requirement. **Defer unless user wants multi-worker now.**
- **J-D4 — chat mid-stream failover**: failover applies at **stream start** only; a provider failing mid-stream surfaces as an error rather than transparently re-issuing on the next provider (re-issuing mid-stream would double-emit tokens). *Recommendation*: accept the start-only limitation for V1; document it. Confirm acceptable.
- **J-D5 — default global privacy mode**: plan seeds `default_privacy_mode = 'cloud'` (matches Track J's "cloud by default"). A privacy-first operator flips one setting. Confirm `cloud` is the right ship default vs. `private`.
