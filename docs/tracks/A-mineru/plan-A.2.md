## 4. Acceptance criteria (numbered, testable)

1. **Settings dropdown** renders four `<SelectItem>` values (`simple`, `docling`, `mineru`, `auto`). Selecting `auto` makes the `docling_min_confidence` Slider appear; selecting anything else hides it. (Maps to prompt criterion #1.)
2. **Slider round-trip**: setting slider to e.g. `0.85`, clicking Save, reloading the page → slider re-renders at `0.85`. Verified via `PATCH /api/settings` payload includes `docling_min_confidence: 0.85` and `GET /api/settings` returns it. (Prompt #2.)
3. **`ParserEngineBadge` four visual states** (Prompt #3):
   - `metadata.parser_engine_used === 'docling'` and not `extraction_fallback_triggered` → renders nothing (or a subtle gray "Docling" badge with `variant="secondary"`; **decision**: render nothing, matches "default, no badge" in prompt spec).
   - `metadata.parser_engine_used === 'mineru'` and not `extraction_fallback_triggered` → blue badge "MinerU" (`variant="default"`, `bg-blue-700`, `WandSparkles` icon).
   - `metadata.extraction_fallback_triggered === true` → amber badge `MinerU (auto-fallback, conf {extraction_confidence.toFixed(2)})` (`bg-amber-600`, `AlertCircle` icon). Hover-tooltip shows the per-signal confidence breakdown from `extraction_confidence_signals`.
   - Legacy: `metadata == null` OR no engine recorded but `source.status === 'error'` → red badge "extraction failed" (`bg-red-700`, `XCircle` icon).
4. **Health chip polls every 30s** (Prompt #4). Use React Query `refetchInterval: 30_000`. Verified by Playwright spec that mocks `/api/health/mineru` to flip from `healthy: true` to `healthy: false` after first poll and asserts the chip changes state within 35s (one interval + 5s slack).
5. **`GET /api/health/mineru`** (Prompt #5) returns `{healthy: true, version: "..."}` when mineru container is up, `{healthy: false, error: "..."}` when down. Never returns 5xx — the endpoint itself is always 200. Backend integration test in `apps/app-main/tests/test_health_router.py` mocks `MineruHttpClient.health_check` to cover both branches.
6. **Per-source override** (Prompt #6): the reparse modal Select defaults to `"Use default"` (value=`""`). Choosing `mineru` and clicking Reprocess results in a `POST /sources/{id}/reprocess` body with `parser_engine: "mineru"` (assert in spec via `page.route` intercept). Backend already supports this.
7. **Playwright specs pass locally and in CI** (Prompt #7): `npx playwright test e2e/track-a/` is green; specs that depend on the mineru container being up are guarded by `test.skip(!process.env.MINERU_AVAILABLE, '...')` — CI runner has no GPU so MinerU is unavailable. Health-chip + settings-roundtrip + badge + override specs use **route mocking** (`page.route('**/api/health/mineru', ...)`, `page.route('**/api/sources/**', ...)`) so they run on CI without the mineru container. The four specs are added to `.github/workflows/e2e.yml` automatically because `testDir: './e2e'` already globs them.
8. **`tsc` + `next lint` clean** (Prompt #8): no `any`, no console errors in `next dev` startup. Run `cd frontend && npx tsc --noEmit && npm run lint` before commit.
9. **A11y labels** (Prompt #9): every form control has either an explicit `<Label htmlFor>` or an `aria-label`. The Slider gets `aria-label="Docling confidence threshold"` (Radix Slider also auto-sets `aria-valuenow/min/max`). The Select trigger inherits its accessible name from the preceding `<Label>`. The health-chip has `aria-live="polite"` and `role="status"` so screen-reader users hear status changes.
10. **Badge component test** (Prompt #10): vitest is **not** currently in `package.json`. Default ships a Playwright spec (`parser-engine-badge.spec.ts`) that mounts the source-detail page with stubbed API responses and asserts each of the four badge states. If user prefers a true unit test, see §5 open question.

The aggregate endpoint can additionally include mineru in a follow-up. **No escalation needed unless reviewer disagrees.**

## 8. Risks + mitigations (focused; track-level risks live in parent plan)

- **Risk**: `useMineruHealth` polls every 30s indefinitely → wastes battery on background tabs. **Mitigation**: React Query already pauses `refetchInterval` when the tab is hidden (`refetchIntervalInBackground: false` is the default). No code needed; verify by tab-switching during manual QA.
- **Risk**: Playwright route-mock specs become stale if API contract drifts. **Mitigation**: spec files import types from `@/lib/types/api`; a contract change forces type errors at spec-compile, surfaced by `tsc`. (`@playwright/test` runs through `tsconfig`.)
- **Risk**: The badge "extraction failed" red state may conflict with the existing Zotero red badge at line 581-585. **Mitigation**: badge order: `ParserEngineBadge` first, Zotero last — visually separated. Manual QA confirms the row remains readable when both are present.
- **Risk**: `next lint` may flag unused imports in `SourceDialog.tsx` after the prompt's mention — but `SourceDialog.tsx` is the **wrapper** around `SourceDetailContent` and does not need editing. Plan reflects the actual file structure (reparse dialog lives inside `SourceDetailContent`).
